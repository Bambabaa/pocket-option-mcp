## 2. Data Tools (6)

### `po_candles`
**Category:** Market Data  
**Database:** Bot DB (readonly)  
**Purpose:** Get OHLC candle bars for an asset

**Parameters:**
- `asset` (required) - Asset symbol, e.g. `EURUSD_otc`
- `limit` (optional, default 100) - Number of candles (1-1000)

### `po_trade`
**Category:** Orders  
**Database:** MCP DB (write)  
**Purpose:** **Place a manual CALL or PUT trade**

**Parameters:**
- `asset` (required) - Asset symbol, e.g. `EURUSD_otc`
- `direction` (required) - `CALL` or `PUT`
- `amount` (optional) - Trade size USD (uses bot default if omitted)
- `signal_timestamp` (optional) - Unix seconds (defaults to now)

**Returns:**
- `success` - Boolean
- `order_id` - MCP order ID
- `message` - Confirmation

**Flow:**
1. Writes `PENDING` row to `mcp_orders` table
2. Bot's `runMcpOrdersWorker()` polls and picks it up
3. Bot atomically claims order (prevents double-execution)
4. Bot checks `asset_controls` for blocks
5. If clear, executes via `executeOneOrder()` → clicks DOM
6. Updates status to `EXECUTED`/`SKIPPED`/`FAILED`

**Use Case:** Manual trade placement, testing strategies, agent-driven execution.

**⚠️ Important:** If asset is blocked via `po_block_asset`, order will be picked up but immediately set to `SKIPPED`. Check `po_asset_volatility` first.

### `po_find_edge`
**Category:** Research  
**Database:** Bot DB (readonly)

**Parameters:** None

**Returns:**
Win rate breakdown by:
1. **RSI range** - e.g. RSI 20-30, 30-40, etc.

10. **MA gap trend** - Was gap narrowing (exhaustion) or widening?

**Use Case:** "Where is the edge?" Find which conditions produce best WR. Research-grade analysis.

**Use Case:** Review what agents did and why. Debugging multi-agent pipeline.

### `po_block_asset`
**Category:** Multi-Agent  
**Database:** MCP DB (write)  
**Purpose:** **Block an asset** from being traded

**Parameters:**
- `asset` (required) - Asset symbol or `"ALL"` to emergency-stop everything
- `reason` (required) - Why (logged for audit)
- `source` (optional, default `claude`) - Who is blocking (`claude`, `analyst`, `user`)
- `duration_minutes` (optional) - Auto-expire after N minutes (omit = permanent)

**Returns:**
- `success` - Boolean
- `message` - Confirmation
- `expires_at` - Unix timestamp (if timed block)

**Flow:**
1. Writes to `asset_controls` table
2. Bot checks `isAssetBlocked()` before every order
3. If blocked, order is set to `SKIPPED`

**Use Case:** Block flat/pegged assets, broken indicators, losing assets. Use `asset="ALL"` for emergency stop.

### `po_asset_volatility`
**Category:** Multi-Agent  
**Database:** Bot DB (readonly)  
**Purpose:** **Rank all assets by BB width** — find flat/pegged assets

**Parameters:**
- `min_bb_bps` (optional, default 0) - Only return assets ≥ this BB width

**Returns:**
Array of assets ranked by volatility (highest first) with:
- `asset` - Symbol
- `avg_bb_bps` - Average BB width (basis points)
- `rating` - `GOOD` (≥10), `MARGINAL` (5-10), `WEAK` (2-5), `FLAT` (<2)
- `is_blocked` - Boolean (current block status)
- `block_reason` - If blocked
- `total_pnl` - All-time P/L

**Formula:** `bb_bps = (bb_upper - bb_lower) / bb_middle × 10000`

**Use Case:** **Find flat assets to block.** `FLAT` (<2 bps) = dead market = losing zone.

### `po_auto_block_check`
**Category:** Multi-Agent  
**Database:** Both  
**Purpose:** Check if asset should be auto-blocked based on today's performance

**Parameters:**
- `asset` (required) - Asset symbol

**Returns:**
- `should_block` - Boolean
- `reason` - Why (if blocked)
- `today_stats` - Today's trades, WR, consecutive losses
- `action_taken` - `BLOCKED` or `NO_ACTION`

**Triggers:**
- **3+ consecutive losses today** → 120-min block
- **Win rate < 35% with 5+ trades today** → 120-min block

**Use Case:** Call after every trade result. Timed blocks auto-expire.
